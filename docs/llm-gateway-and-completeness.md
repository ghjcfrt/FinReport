# LLM 中转站与分析完整性

## 接入与配置

分析客户端支持 OpenAI 兼容的 `/chat/completions`，可选择普通 JSON 响应或 SSE 流。已有 OCR 使用独立客户端配置，不继承分析模型的流式和供应商路由选项。

新中转站可在仓库根目录 `.env` 中配置以下选项，连接地址、密钥和模型沿用 `FINREPORT_LLM_BASE_URL`、`FINREPORT_LLM_API_KEY`、`FINREPORT_LLM_MODEL`。不要把真实密钥写入本说明或提交记录。

```dotenv
FINREPORT_LLM_STREAM=true
FINREPORT_LLM_PROVIDER_SORT=price_multiplier
FINREPORT_LLM_ENABLE_THINKING=false
FINREPORT_LLM_REASONING_EFFORT=
FINREPORT_LLM_STRUCTURED_OUTPUT_MODE=json_object
```

`provider_sort` 生成顶层 `provider.sort=price_multiplier`，与示例 SDK 的 `extra_body` 合并结果相同。客户端不发送空的供应商筛选数组，不限制候选供应商。该参数表达价格优先策略；是否按策略路由以及最终收费由中转站决定，客户端不凭请求参数证明最终选中了最低价。

需要验证返回思考时，将 `FINREPORT_LLM_ENABLE_THINKING` 设为 `true`。`reasoning_effort` 是独立的可选协议扩展；留空则不发送，避免将旧供应商的配置强加给新供应商。改动 `.env` 后重启 API；已设置的进程环境变量优先于该文件。

## 接收、展示与证据

SSE 接收器分别拼接 `delta.reasoning_content`、正文和原生工具调用的分片，接受无 `choices` 的 usage 尾包。只有完成标记与响应结构通过校验，才能把结果交给分析流程。中断、超时、截断和供应商错误保留已收到的内容及错误分类。

工具动作仍使用已注册函数及严格参数校验；普通报告结构仍经原有数值、引用与语义校验。支持流式不意味着放宽金融结果准入。

审计轨迹保存脱敏请求、SSE 事件、聚合响应、供应商返回的思考字段和哈希。离线回放同时核对事件与聚合结果，旧的非流式轨迹继续使用原来的协议。哈希可发现相对保存基准的改动，不能代替独立数字签名或证明公司披露真实。

报告试验分析界面和 HTML 导出可展开查看供应商返回的思考正文，按调用轮次标识；关闭思考和未返回正文分别显示。这里只展示供应商实际提供的文本，不能据此验证模型内部推理是否完整、真实或正确。

## 分析完整性的验收范围

新的逐项清单与已有义务覆盖并行，重点阻止已经取得的非经常性损益构成被一句“没有其他项目”替代。清单绑定文件、期间、原文范围、金额和行角色；跨页续表、扣减、合计及不明确的解析状态必须保留。解析失败或缺少续页不能通过空分母得到 100%。

覆盖报告回答的是结果是否明确呈现并处置所列证据。它不能直接观察模型内部是否注意到了某段材料，也不证明因果判断正确。其他财务主题仍需结合各自的分析义务、引用与材料缺口理解，不能把一个表的逐行通过宣称为整份报告语义分析完整。

人工审核与覆盖检查分开：清单闭合、金额勾稽和逐项处置通过，均不会自动把待审原文或候选金额升级为已审核事实。

## 当前实现

新运行采用 `evidence_obligations_v3` 和 `pending_row_sources_v2`。非经常性损益清单包含构成、扣减和合计；覆盖结果同时保留清单哈希、表内复算、逐行原文、模型实际输入记录、显式处置和待补项。已发送状态按各轮真实请求的来源及文本哈希重建，避免把“已检索”“已送入”“结果已呈现”混为一项。

有遗漏时，待处理行的真实来源优先进入当前窗口，最多执行两次定向补分析，且受总动作轮数约束。补分析提示只要求待补项；未完成的其他义务继续保留。模型返回非法 JSON、额外字段、错误类型、无依据金额、方向或因果断言时，仍然拒绝并保存原始输出。

说明理由可以使用同文档同列唯一的原文主标签，程序只允许去除完整配对的尾部括注；呈现的认证原文仍保留完整标签和限定语。该规则避免长标签复述造成误拒，不证明模型已正确理解所有限定语。

历史 V1/V2 及旧 V3 的提示、上下文和校验按保存的策略版本重建。新策略不能静默改变旧记录的原始拒绝结果。

## 测试与结果状态

真实实验和复现记录保存在本地忽略目录 `tmp/gateway-completeness-20261017/`；详细报告为该目录下的 `validation-report.md`。记录分别保留原始输入、逐次供应商响应、SSE 事件、准入或拒绝原因、源码清单和离线回放。

`evidence_coverage.complete=true` 仅表示该逐行专项的呈现和处置已闭合。整体任务仍可能是 `waiting_for_documents`、`partial_result` 或待审核：例如只选半年报，单季环比仍缺一季报精确金额；没有人工审核，也不会自动形成已确认财务事实。

验收尚未覆盖所有财务表格、全篇长报告或多发行人的人工盲测集。后续需要独立验收清单漏项、语义支持关系和不同模型重复运行的一致性。
