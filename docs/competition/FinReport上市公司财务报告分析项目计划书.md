# FinReport 上市公司财务报告分析研发项目计划书

项目方向：2026 年北京市大学生金融人工智能竞赛“上市公司财务报告分析”  
计划书基线：2026 年 10 月 18 日  
项目状态：可运行原型与受限样本验证阶段

## 一 项目摘要

FinReport 面向 A 股上市公司年度、半年度和季度财务报告，建设一套能够从原始披露材料提取财务事实、保存经营叙述、执行口径受控的本地计算，并让大语言模型按需检索证据、解释业绩变化和提示异常线索的分析系统。目标不是让模型一次性阅读整本报告后直接给出结论，而是把长报告、财务表格和叙述性附注保存在项目控制的数据层中，由分析流程围绕具体问题调用受限的检索、事实、比较和补件工具。

本项目针对赛题考察的同比与环比、非经常性损益、会计口径变化、利润与现金流背离等问题，正式版目标采用“原始披露—候选数据—自动校验与候选标记—确定性计算—证据检索—分项分析—报告呈现”的流程。金额、单位、期间、合并范围、来源页和校验状态随事实一起保存；财务公式由程序执行；模型负责组织分析问题、查找相关材料和解释证据关系。对现有材料无法确认的事项，系统明确列出证据边界与待补材料，不把“未检索到”写成“公司没有披露”，也不把质量检查通过写成“公司没有财务异常”。

截至本计划书基线，项目已有桌面端、API、提取和分析流程、财务公式、SQLite 证据存储、Qdrant MCP 检索及本地 Unlimited-OCR 部署。当前验证集中于比亚迪 2025 年半年度报告的 7 个选定页，以及四份 2025 年报告的少量检索页。固定选页试验最终形成 3 项待校验候选、5 项证据不足，尚无测试金标准评测记录；这说明流程能够保留校验缺口与证据边界，不代表完整报告已分析或赛题要求已全部验收。本计划书将后续工作拆为 WP0-WP10 工作包和 G0-G7 退出 Gate，优先完成全文、多发行人、测试金标准评估、误差归因和演示环境复现评测。

本计划所称测试复查，均仅用于评测与误差归因，不属于正式运行流程。自动校验准入与四类校验状态是 WP4 的研发目标，历史选页实验按原流程记录，不作为新校验状态机已实现的证据。

## 二 项目背景与问题定义

上市公司财报同时包含结构规则不同的报表、复杂表格、管理层讨论、会计政策和重要事项附注。单纯抽取可见数字会丢失主体、期间、单位、合并范围、调整关系及表格行列关系；直接要求大语言模型总结长文又容易遗漏材料、混淆报告版本或生成没有来源支持的因果解释。同比和环比还依赖报告期间及累计口径，半年度或前三季度的累计数不能直接当作单季度数据比较。

本项目将问题拆成四类可检验工作：

1. **材料与版本管理。** 保留原始 PDF、文件哈希、报告类型和期间；更正稿及不同季度报告作为独立版本管理，分析范围由用户显式选择。
2. **事实提取与口径确认。** 分离结构化金额事实和非结构化披露文本，保存来源定位、单位、期间、主体和校验状态；解析候选不自动成为自动校验通过事实。
3. **程序化计算与异常识别。** 以自动校验通过且来源可追溯的同口径事实计算指标与期间变化，再结合规则和披露证据识别需要解释的异常信号。
4. **证据驱动的解释。** 让模型按子问题查询本地材料和计算记录。证据不足时请求具体文件、期间或附注，不推断缺失材料的内容。

## 三 项目目标与范围

### 3.1 项目目标

- 支持年度、半年度和季度报告的分版本入库、页选择、文本及金额候选提取。
- 同时保存结构化事实和可检索的叙述性证据，确保结论可回到报告原文。
- 计算有明确公式、期间和口径的财务指标及同比、环比变化；对负数基期、零分母、缺少比较期或口径不一致给出明确状态。
- 围绕非经常性损益、会计政策或估计变化、前期差错与重述、合并范围、持续经营、利润与经营现金流背离建立分项分析任务。
- 输出结构化结果或分析报告，并区分公司披露、程序计算、分析推断、待校验候选和证据不足。
- 保存运行输入、访问文件、检索与工具调用、原始模型响应、计算记录、源码/依赖版本和结果哈希，支持离线回放。

### 3.2 当前范围

首期面向中国 A 股非金融企业。严格数值通路优先覆盖人民币、合并口径、完整自然年度及具有标准无保留审计意见的高保证样本；非标准审计意见保留原文和审计意见状态并标记为受限，后续 WP5/WP7 将其作为异常或风险披露纳入分析，不因意见类型而静默丢弃。半年度、季度、选页和 OCR 数据可进入补充分析流程，但未通过自动校验时不得冒充自动校验通过的严格事实。

系统用于财报研究与风险线索整理，不构成证券投资建议，不自动给出买卖结论，也不替代审计、法律、合规或投资决策。若选用外部模型服务，实际发送给模型的文字和页面范围取决于配置；演示阶段须使用获准样本、记录模型服务及版本，并遵守组委会对数据环境的具体要求。

## 五 总体方案与系统流程

### 5.1 正式版目标流程

1. **导入与隔离。** 用户上传财报，系统先执行文件扫描和哈希计算，再按公司、报告期、报告类型和更正关系保存独立版本。默认一次分析针对一份锚定报告；多份报告只有在用户明确勾选时才会组成比较输入。
2. **选择提取路径。** 用户明确选择原生 PDF 文本/坐标提取或 OCR。原生路径读取 PDF 文字层及位置；OCR 路径将选定页渲染为图像，不读取该任务的 PDF 文字层或文字坐标。解析失败不会静默切换路径。
3. **自动校验与候选标记。** 提取结果先作为候选，执行格式、单位、期间、口径、表格勾稽、来源定位和置信度校验，标记 `auto_passed`、`needs_review`、`rejected` 或 `candidate`。OCR 表格需要完成行列与科目映射；测试金标准评估仅用于评测自动校验的误放和误拒，不进入正式运行流程。校验状态与原文、页码、坐标或图像哈希绑定，材料变化后原校验结果失效。
4. **结构化与非结构化分离。** 数字、币种、单位、期间、主体、报表范围、科目、来源位置和校验状态进入事实与计算数据；管理层讨论、会计政策、重大事项、业务原因等以原文块保存，附章节、页码、哈希和表格关系供检索。
5. **本地预处理与检索。** 可选 Docling MCP 对已选 PDF 页生成含章节和表格关系的结构化文档。证据块写入 SQLite 权威存储，并可同步到 Qdrant MCP；Qdrant 按报告版本过滤并负责召回，SQLite 保存权威文本和可复核来源。检索服务不可用时可退回确定性关键词查询。
6. **确定性计算。** 严格通路只读取自动校验通过且来源可追溯、口径满足条件的事实。报告金额试验通路可以对候选执行可复算算术，结果标记为 `candidate_arithmetic` 并继承校验状态，不升级为严格事实。两条通路均保存公式版本、输入来源、比较期间、单位和异常状态；模型不能自行编造或改写程序结果。
7. **分项分析与按需取证。** 语言模型使用有限工具查询文件目录、指定文本块、事实、比较计算或待补材料。系统按子命题处理候选，保存每轮请求、响应、工具参数和准入/拒绝原因；缺失材料时返回 `waiting_for_documents` 或不完整状态。
8. **报告与结果检查。** 结果按公司披露、程序计算、分析推断、待校验及证据不足分类。每项结论展示引用和适用期间；用户可查看原文或要求补充材料后续分析。

校验状态定义为：`candidate` 表示尚未完成校验；`auto_passed` 表示必需规则全部通过且来源可追溯；`needs_review` 表示来源、结构或口径仍有疑点，保留结果并由补证、重新提取或规则重算处理；`rejected` 表示违反硬性规则，阻断该候选进入严格计算。`needs_review` 不设置人员处理的正式准入要求。置信度高或表格合计相符不能单独将事实升级为 `auto_passed`；自动校验通过也不等于原始披露真实或业务因果已确认。

### 5.2 系统组成

| 层次 | 主要组件 | 责任 |
| --- | --- | --- |
| 桌面交互 | .NET 10 WPF | 文件选择、提取方式选择、自动校验状态、分析任务及结果查看 |
| API 与工作流 | FastAPI | 接收请求、任务状态、接口权限边界、结果和审计记录 |
| 领域与应用 | Python `uv` workspace | 财务口径、公式、事实准入、分析任务和工作流编排 |
| 解析与模型适配 | PyMuPDF、Unlimited-OCR、Docling MCP、OpenAI 兼容 LLM 客户端 | 文本/图像识别、结构化预处理和受控模型调用 |
| 本地证据存储 | SQLite 与对象目录 | 权威保存文件信息、事实、文本块、校验日志、计算和回放输入 |
| 证据检索 | Qdrant MCP | 向量召回和报告版本过滤；不承担事实批准或财务计算 |
| 文件安全 | Rust Scanner Supervisor 与 ClamAV | 文件进入解析前执行扫描，扫描错误时阻断处理 |

当前 API 使用 FastAPI 后台任务执行分析；仓库存在 Celery Worker 组合根，但未完成 Celery/Redis 多进程生产部署验收。系统目前以本地演示配置为主，PostgreSQL 可配置但不代表生产数据库部署已经验证。

### 5.3 研发任务分解

本项目按工作包（Work Package，WP）管理研发活动。每个工作包单独登记依赖关系、下一 Gate 交付和退出证据。

| 编号 | 工作包 | 当前基线 | 前置依赖 | 下一 Gate 交付 | 退出标准 |
| --- | --- | --- | --- | --- | --- |
| WP0 | 基线与研发治理 | 已有代码路径 | 无 | baseline manifest、代码/配置/依赖清单、风险登记 | 输入哈希、报告版本和运行命令冻结；保存响应的离线回放可运行 |
| WP1 | 材料与版本管理 | 已有代码路径 | WP0 | corpus manifest、报告版本关系、缺件清单 | 样本文件均有哈希和期间元数据；未显式选择的报告不会进入检索或计算 |
| WP2 | 原生 PDF 与 Unlimited-OCR 双路径提取 | 已有代码路径 | WP1 | 双路径 extraction bundle、页级质量报告 | 两条路径不静默互相回退；金额、科目结构、单位和期间分层评测 |
| WP3 | 结构化与非结构化分离 | 已有代码路径 | WP2 | fact candidate、table unit、text chunk 和来源映射 | 严格事实可回到页、文本块或行列；无法闭合的表格只保留候选 |
| WP4 | 自动校验与测试金标准评估 | 仅有设计 | WP2、WP3 | 校验规则、测试金标准、误差分类账 | 格式、单位、期间、口径、勾稽和来源规则覆盖；严格计算只接受 `auto_passed`；测试金标准样本可评估误放/误拒 |
| WP5 | 财务口径与确定性计算 | 已有代码路径 | WP3、WP4 | fact ledger、calculation ledger、公式版本和边界用例 | 独立参考实现对照通过；零/负基数、缺比较期和口径不一致时拒算 |
| WP6 | 证据检索与受控 Agent | 已有代码路径 | WP1、WP3、WP5 | obligation trace、检索基准、补件清单 | 每项结论有引用或明确不足；选页缺证据时返回 `waiting_for_documents` |
| WP7 | 异常规则与原因分析 | 已有代码路径 | WP5、WP6 | rule registry、正反例集、语义守卫记录 | 规则只触发核查，不直接判定舞弊；业务因果必须有原文支持 |
| WP8 | 报告、审计与复现 | 已有代码路径 | WP5、WP6、WP7 | 报告 schema、replay bundle、脱敏样例 | 冻结输入和保存响应可离线确定性回放；外部模型复跑只比较预定义类别和数值容差 |
| WP9 | 评测与误差归因 | 待启动 | WP2-WP8 | evaluation report、误差分类账 | 按提取、计算、证据、异常、复现和自动校验分别报告样本量与结果 |
| WP10 | 干净环境与演示验证 | 待启动 | WP0、WP8、WP9 | 安装说明、演示脚本、版本/许可证清单、备份包 | 目标环境完成上传、提取、校验、计算、检索、报告和证据回查；外部模型不可用时可走离线回放 |

WP4、WP9 和 WP10 是当前最明显的研发缺口。WP0、WP1-WP3、WP5-WP8 已有代码路径或受限样本基础，但这只表示存在可运行路径，不表示已通过全文、多发行人或竞赛级准确率评测。

### 5.4 关键难点与攻关计划

| 难点 | 研发攻关方法 | 失败处置 |
| --- | --- | --- |
| 数字识别正确但科目、行列或期间关系错误 | 将金额、结构、单位、期间和来源定位分层校验；原生 PDF 与 OCR 分开对照，Docling 只做结构预处理 | 保留为候选并要求科目映射、自动校验与测试金标准抽样评估，不升级为严格事实 |
| 累计值、单季值、重述值和合并范围混用 | 在公式入口统一校验期间、主体、口径和报告版本；对累计差分、直接披露冲突和非正基数设置反例 | 拒算并请求相邻报告、重述说明或相应附注，不用缺失值补零 |
| 审计意见文字变体导致准入误判 | 保留审计意见原文，同时建立“无保留、保留、否定、无法确认”等规范化标签；严格准入只使用已登记的规范值 | 无法确认或非标准意见不静默丢弃，转为风险披露或受限计算；先修正规范化再进入高保证通路 |
| 长报告证据未进入当前模型窗口 | 先在本地保存全文、文本块和事实，再按子问题调用受限检索；记录实际发送范围和召回版本 | 只报告当前证据边界并提出补件，不把检索未命中写成全文未披露 |
| 模型因果越界或协议字段错误 | 原始响应、工具轨迹和拒绝原因全部留痕；使用固定 schema、有限重试和语义守卫 | 拒绝候选，必要时只重交失败任务，不静默改写模型原话 |
| 自动校验误放/误拒缺少测试金标准样本 | 按格式、单位、期间、口径、勾稽、来源和置信度建立规则，并登记边界样本 | 保留 `needs_review`，按测试金标准抽样评估并将误放/误拒回写规则；测试金标准评估不进入正式运行流程 |
| 外部模型、OCR 或检索服务变化 | 锁定模型/权重/依赖版本，记录配置和发送范围，准备脱敏 replay bundle | 外部服务不可用时展示离线回放；把本地确定性回放和模型重新调用分开报告 |

## 六 财务分析方法

### 6.1 统一事实口径

每个金额至少附带公司、报告版本、科目、币种与单位、期间起止、时点/期间属性、合并/母公司口径、原文页码或文本块、提取方法及校验状态。跨报告计算前先核对这些字段。更正稿与原披露保持版本关系，不覆盖原件；追溯重述前后的比较值需要明确采纳哪个披露口径，并保存理由。

### 6.2 同比与环比

同比使用相同报告期间和相同口径的上年同期或上年全年值。季度报告中的累计金额不能直接当成单季金额：若报告提供年初至今累计值，试验通路按 Q2 = 半年累计 - Q1，Q3 = 前三季度累计 - 半年累计，Q4 = 全年累计 - 前三季度累计推导单季期间流量，再与上一单季比较。存量科目是时点值，不通过累计差分转换。环比计算前需检查前期金额是否为零、负值或口径变化；不适宜计算百分比时展示金额变化并说明原因，不输出误导性百分比。

季度派生设计包含累计差分、单季环比/同比、直接披露冲突校验和非正基数拒算。跨报告差分仅在用户显式联合报告时执行；当前尚不能独立剔除合并范围和政策变化的影响。未通过自动校验的金额和计算，报告必须明确标记为候选或受限结果，全文、多发行人和重述案例纳入后续评测。

### 6.3 非经常性损益与会计口径

目标数据模型按公司披露表逐项保存非经常性损益的税前构成、所得税影响、少数股东影响和净额，不用模型概括替代原表。当税项、少数股东影响、跨页续表或归母桥接缺失时，保留候选并阻断严格准入。归母净利润与扣除非经常性损益后归母净利润仅在公司、期间、单位和口径一致时比较。若项目表不完整、跨页续表缺失或合计勾稽不一致，则指出缺少行、页或附注，不以空值或未检索到充当零。

会计政策与估计变化、前期差错及追溯重述、同一控制下企业合并、合并范围变化及持续经营披露分别作为分析主题。报告索引、一般性政策文字或模型未命中不能证明事项不存在；判断需要引用对应附注，材料不在当前选定范围时请求用户补充或确认。

### 6.4 利润与经营现金流背离

合并口径的经营现金流调节使用合并净利润，包含归属于母公司和少数股东的损益；归母净利润另外列示，用于股东收益分析，不能直接替代调节表起点。程序列示相同公司、期间及合并范围的净利润和经营活动现金流量净额、现金利润比、符号及期间变化，并在可验证的表格边界内读取和核验调节项；完整间接法调节表作为后续评测项。现金流为负或净利润为零、负数时，不机械解释现金利润比等比率。

应收款、存货、应付款、折旧摊销等调节项能够解释会计利润与现金流之间的数值桥接，但不能单独证明销售、回款政策、价格或供应链原因。原因分析必须由管理层说明或其他业务附注支持；证据缺失时只呈现量化背离和待补材料，不给出未经证实的业务归因。

### 6.5 异常信号与结果分类

异常分析同时考虑可计算信号和文本披露风险。异常分析设计包含利润与 CFO 变化方向的比较信号，以及非经常性损益贡献计算；收入与应收项目变化、费用和毛利率异常的自动规则与阈值属于后续扩展及评测范围。信号只触发核查任务，不直接等同舞弊或经营恶化。文本风险必须由披露原文支持，例如审计意见、持续经营重大不确定性或重述事项。

输出中的公司披露是逐字或受控摘录；程序计算附公式和输入；分析推断说明推理依据与限制；证据不足列明尚需材料。质量状态回答“输入及处理能否进入分析”，不能代替“公司是否存在财务异常”的判断。

## 七 项目特点

### 7.1 与传统方案的区别

与传统“整本报告喂给 LLM 后总结”相比，FinReport 的差异是：事实先自动校验再计算，计算与解释分离，按子问题取证而非一次性填满上下文，不确定性作为正式结果，运行证据可离线回放。该路线不以模型生成替代程序计算，也不以质量检查通过替代财务异常判断。

### 7.2 项目特点

1. **先自动校验事实，再做严格计算。** OCR、文字提取和表格解析先生成候选，来源映射和校验状态随值传递，模型不能跳过事实准入。
2. **结构化数值与叙述证据分开保存。** 严格公式读取自动校验通过的事实，候选演算另带待校验标记；解释性附注通过有版本和来源的文本块检索，不把长篇全文压缩为一段摘要后丢失可追溯依据。
3. **按问题取证，而非一次性填满上下文。** 受控 Agent 可以根据未解决的子问题读取相关页、文本块和计算结果，也可以请求特定报告或附注。工具范围受限，不允许模型任意访问路径、SQL 或系统命令。
4. **把不确定性作为正式结果。** 对未通过自动校验、口径不匹配、数据不足或因果证据缺失分别保留状态；不把系统降级、检索空结果或质量通过解释为“无异常”。
5. **保留运行证据供离线复现。** 保存原始输入、模型响应、工具交互、版本和哈希。可以离线重放冻结运行；不会据此宣称供应商模型的新一轮调用必然得到相同文本或结论。
6. **研发管理可检查。** 以 WP0-WP10 工作包和 G0-G7 Gate 管理研发，每个 Gate 提交结果、日志、输入哈希和未通过项；Gate 通过只表示对应工作包达到退出标准，不代表整份财报或全部金融结论已验收。

## 八 当前基础与试验结果

### 8.1 已有实现

- `.NET 10 WPF` 桌面端、FastAPI API 和基于 `uv` 的 Python workspace 已形成端到端原型。
- 已支持用户显式选择 `pdf_text` 或 `ocr`；原生路径读取文字和坐标，OCR 路径对选定页面图像调用 Baidu Unlimited-OCR。本机 OCR 服务通过 CUDA 与 NF4 运行，不依赖 DeepSeek-OCR。
- 本地 Docling MCP 以关闭 OCR/VLM 的配置为文本结构化预处理；Qdrant MCP 使用真实 CPU embedding，并以 `filing_version_id` 限制跨报告召回；SQLite 保留权威来源和降级查询。
- 分析 Agent 通过注册工具执行检索、读取文本、查询事实/比较和提出补件请求；独立子命题具备有限重试、候选准入、失败原因和任务恢复记录。
- 测试环境的 Python 测试套件最近一次全量运行结果为 810 passed、12 warnings。该结果验证软件行为，不是财报数据准确率。

## 九 验证与评测计划

### 9.1 测试集与金标准

建立经授权的发行人和报告样本集，记录文件 SHA-256、报告版本、页码、期间、合并范围及更正关系。按赛题主线覆盖年报、半年报、季度报告、复杂表格、扫描页、非经常性损益、追溯重述、会计政策/估计、合并范围变化、单位差异、累计与单季换算以及利润现金流背离。测试金标准由评测流程独立标注，仅用于评测；冲突按预先登记规则裁定，不进入正式运行流程。标注结果只用于评估自动校验和模型输出；同一指标需附原文定位、单位、公式和容差。

在至少 5 家发行人完成覆盖样本之前，不将金融模块标记为跨公司 `supported`。每份报告要区分训练/调试样本与保留评估样本，避免用已调试页面同时报告准确率。

### 9.2 评测指标

| 维度 | 主要指标 | 验收方式 |
| --- | --- | --- |
| 文档提取 | 核心指标 exact match、行列/单位/期间匹配率、来源定位正确率、表格遗漏率 | 与逐页测试金标准标注对照；原生 PDF 与 OCR 分层报告 |
| 财务计算 | 公式值偏差、期间和口径错误数、应拒算案例通过率 | 独立参考实现重算；零/负基数、重述和累计期间作为反例测试 |
| 证据使用 | 结论引用支持率、未支持断言率、材料命中及遗漏情况 | 对模型每项事实与因果判断标注证据是否充分 |
| 异常识别 | 精确率、召回率、误报类型及证据定位率 | 在预先标注的异常和正常样本上评估；没有证据的异常不计为确认发现 |
| 可复现性 | 冻结输入离线回放通过率、日志完整率、跨运行结论分类一致率 | 首先复放同一保存响应；另对同模型独立运行至少 3 次，仅比较预定义结论类别及数值容差 |
| 自动校验与测试金标准评估 | 自动校验覆盖率、`needs_review` 比例、误放率、误拒率、测试金标准一致率和规则修正率 | 按测试金标准抽样评估，仅评估规则，不作为正式运行准入 |

验收阈值应在金标准数据形成后，由指导教师和项目组根据风险预先登记，不能在看到结果后调整；准确率、召回率和成本均报告样本量与置信边界。尚无完成的金标准结果时，本计划不虚构数值门槛或准确率。

### 9.2.1 阶段性指标与 Gate 证据

以下是研发目标和验收方法，不是当前成绩。阈值在金标准形成前登记，当前只报告已经测得的样本结果。

| 维度 | 阶段目标 | Gate 证据 |
| --- | --- | --- |
| 材料完整性 | 计划样本登记率 100%，哈希/版本关系缺失数为 0 | corpus manifest、文件哈希和版本关系图 |
| 版本隔离 | 未显式选择的报告被召回或参与计算次数为 0 | 跨报告泄漏反例、查询参数和计算输入日志 |
| 提取与结构 | 原生 PDF/OCR 分层报告金额、科目、行列、单位、期间和来源定位指标 | 双路径 extraction bundle、逐页金标准对照、遗漏分类账 |
| 自动校验与测试金标准评估 | 进入严格计算的事实必须为 `auto_passed` 且来源可追溯；统计 `needs_review` 比例、误放率、误拒率和测试金标准一致率 | 校验规则覆盖、阈值、测试金标准抽样评估及误放/误拒分类账；测试金标准评估仅用于评测 |

| 复现与工程 | 冻结输入/响应离线回放通过数/总数达到 100%；日志字段完整；延迟、token、费用和资源占用实测登记 | replay bundle、安装记录、资源/费用日志和演示报告；回放总数以冻结包 manifest 登记为准 |

### 9.3 可复现的演示运行

每次评测包包含脱敏或公开样例、输入文件哈希、选择的报告 ID 和页码、`uv.lock`、OCR/Docling/Qdrant/LLM 版本与配置说明、运行命令、输出报告、结构化结果、校验日志及离线验证脚本。禁止将 API 密钥写进仓库或样例；评测机器无法访问外部模型时，使用保存响应回放模式，并把“离线重放”与“演示环境模型调用”清楚区分。

### 10.1 研发阶段与 Gate

按 G0→G7 顺序推进，具体时间随研发进展调整；Gate 只表示对应研发包的检查节点，不绑定竞赛日期。

| G4 专项与异常 | WP5、WP7 | 非经常性损益和会计变更逐项缺件可追踪；利润-CFO有限信号与后续规则分层登记 |
| G5 Agent 与证据 | WP6 | 子命题工具轨迹、实际发送窗口、引用支持率和补件请求可检查；缺证据返回受限状态 |
| G6 校验与复现 | WP4、WP8、WP9 | 校验日志、测试金标准抽样评估、冻结输入/响应回放和误差分类账可追溯；评测阈值与样本量先登记 |
| G7 演示验证 | WP10 | 干净环境完成上传、路径选择、校验、计算、检索、报告和证据回查；外部模型不可用时可执行回放 |

每个 Gate 必须同时提交结果、日志、输入哈希和未通过项。Gate 通过只表示对应研发包达到退出标准，不代表整份财报、多发行人或全部金融结论已经验收。

### 10.2 资源、成本与研发控制

原型复用现有 Windows 开发机及 .NET、Rust、Python 工具链。Unlimited-OCR 已在 RTX 4060 Laptop GPU 上用 CUDA/NF4 完成样页验证；现有记录不代表 CPU 可用或其他设备已验收。Docling 文字预处理与 Qdrant 检索使用本地服务；正式演示需锁定模型权重和依赖来源，并预留文件、索引、页面图像和审计日志空间。

模型费用按实际调用的输入、输出 token 数、供应商计费单位和单价逐笔记录；测试复查工时仅作为评测成本记录，不进入正式运行成本。先冻结选页和输出协议，把同一轮可独立判断的子问题合并测试，只重试失败或缺漏任务；开发回归优先采用离线回放。当前没有经过核验的完整报价或工时基线，因此不编造总预算或收益预测；全文试验前先依据小样本测得的延迟、资源占用与调用费用确认预算。

### 10.3 研发变更与失败处置

任务延期、模型更换、报告范围扩大或口径规则调整时，先更新版本清单、依赖和影响范围，再重新运行受影响 Gate。外部服务不可用时切换到冻结响应回放；抽取、计算或模型候选失败时保留原始输入和拒绝理由，降级为 `needs_review`、证据不足或 `partial_result`，不把自动修补后的文本冒充原始结论。

## 十一 风险与应对

| 风险 | 当前影响 | 应对方案 |
| --- | --- | --- |
| PDF/OCR 表格结构错误 | 金额可能正确但科目、期间或列关系错误 | 保留原页，执行自动校验、来源映射和测试金标准抽样评估；分别统计金额与结构准确性；拒绝低置信或无法闭合表格 |
| 同比/环比口径不一致 | 累计值、单季值、合并范围或重述值混用会改变结论 | 计算前执行期间和范围校验；明确派生公式；异常分母或口径不匹配时拒算并说明 |
| 长报告证据遗漏 | 未送入当前上下文的内容可能未被模型使用 | 以本地保存和按需查询补足；记录查询和发送范围；检索未命中时仅报告当前证据边界 |
| 模型生成错误因果 | 相关性或调节项目可能被写成经营原因 | 将计算与解释分开；因果句逐条要求原文支持；用语义守卫覆盖已知错误，不宣称通用语义正确 |
| 自动校验误放/误拒 | 错误事实可能进入严格计算，或有效事实被拒收 | 增加格式、单位、期间、口径、勾稽规则与拒收阈值，保留 `needs_review`；测试金标准样本仅用于评测；误放/误拒结果用于回写校验规则 |
| 外部服务与复现环境变化 | 模型路由、版本、网络或费用可能变化 | 冻结模型标识、参数和响应；使用离线回放备份；演示说明外部调用依赖及数据发送范围 |
| 第三方许可及数据合规 | OCR、检索组件、模型和报告材料有不同来源与授权 | 在提交清单逐项列明版本、来源、许可证、使用范围、数据授权与密钥管理方式 |
| 任务处理与部署韧性 | FastAPI 后台任务尚不等于生产级持久队列 | 后续研发阶段验证任务进程重启、超时、并发限制和失败恢复；未验收前不宣称高可用 |

## 十二 结论

FinReport 已有财报导入、候选提取、程序计算、证据检索和分项模型分析原型及有限页面实验。正式版以自动校验通过且来源可追溯作为严格计算准入，下一阶段按 G1-G7 推进，重点不是继续扩展演示页面，而是把自动校验、全文覆盖、多发行人评测、测试金标准评估和演示环境复现做成可检查的 Gate 证据。所有准确性结论以分层评测结果为准；测试金标准评估只用于评估规则，不属于正式运行准入。
