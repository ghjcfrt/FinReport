# 结构化主张语义评测 v2

> 末尾10例与23项测试来自 v1 生产支持策略阶段，均为历史冻结观测；下文生产准入说明已同步当前 v2 支持策略。新运行策略和来源绑定评测分别版本化，不将旧结果自动升级为新策略通过。

本版本补齐旧评测不读取解释正文的缺口。v1 文件、模型和 `tools/evaluate-analysis.py` 保持原义；不会从旧预测中补造 `reason`，也不会把历史类别一致率改称语义正确率。

## 字段与检查范围

v2 数据集与预测分别使用 `finreport-analysis-evaluation-v2`、`finreport-frozen-predictions-v2`。每个子命题新增 `semantic_claims`，保存：

- 原子主张正文 `claim_text`、可核查简要依据 `basis_summary`；它们不是隐藏思维链。
- 主体、对象及其类型，谓词、否定/不确定性、条件、期间和口径。
- 每条证据的来源 ID、原文哈希、半开区间 `[start,end)`、引文和支持/反驳/背景关系。
- 规则 ID、版本、有来源的前提、规则结果及未获支持状态。

严格评测同时要求旧类别/金额/来源/接纳状态通过，以及结构、证据关系、规则应用、正文和依据符合标签。主体类型错、否定反转、期间错、来源正确却引文范围错均单独计分。正文与依据采用仅归一空白的严格参考匹配，避免模型自报结构正确而错误解释仍获满分；有效改写可能被严格指标误拒，需要单独查看差异，不能把不匹配直接称为事实错误。

`unsupported_claim_rate` 统计需要证据却未获支持的事实/推断。明确的证据不足处置可以作为 `limitation + requires_evidence=false`，不会被当作“没有支持的正面事实”。事实与推断不能关闭证据要求。

这套离线比较不能自动证明原文蕴含主张；生产门禁仍须验证实际冻结原文、span、来源授权与语义支持。模型自报的 `grounding=supported` 不是独立正确性证据。

## DSPy 合同与命令

`build_grounded_analysis_signature()` 返回真实 DSPy `GroundedFinancialAnalysis` Signature。输入为子问题、冻结来源、程序事实和规则目录；输出为逐条有依据的主张及未解决需求。构造 Signature 不创建模型、不请求网络、不运行优化器。定义字段本身不能保证模型遵守，生产验证仍需执行。

该 Signature 目前是可调用的字段合同，**尚未接入生产生成步骤，也未接入 DSPy 优化器、编译训练或提示搜索**。生产模型仍使用项目既有请求和生成路径；不能把 Signature 定义或离线 `Evaluate` 执行称为“DSPy 已改进生产模型的语义推理”。

```powershell
uv run --no-sync python tools/evaluate-analysis-v2.py --print-schema dataset
uv run --no-sync python tools/evaluate-analysis-v2.py --print-schema predictions
uv run --no-sync python tools/evaluate-analysis-v2.py DATASET.json PREDICTIONS.json --output RESULT.json
uv run --no-sync pytest tests/unit/infrastructure/test_analysis_evaluation.py tests/unit/infrastructure/test_analysis_evaluation_v2.py -q
```

数据集标签仍明确声明 `synthetic / regression_reference / independent_gold`，不由 SDK 自动生成金标准。测试只比较保留预测，不能证明新一次外部模型调用会得出相同结果。

## 最终输出门禁与真实能力

当前 `run_analysis` 的新运行在请求和 trace 中记录 `final_semantic_policy=final_claim_support_v2`。模型原始输出完成既有结构、数值与引用检查后，再通过 `_validate_final_semantics`；服务端附加确定性数值文字前后均再次检查。`finalize_analysis_output` 与 `validate_analysis_output` 通过显式 keyword 接受该策略，复现程序依据已保存 trace 中的策略选择相同规则；历史 v1 或无字段运行继续按原规则回放，不追溯宣称已经通过新门禁。财报试验分析通路的工作流另以 `semantic_policy=claim_support_v2` 冻结候选准入策略，不能把最终输出策略字段与工作流策略字段混为一谈。本文旧评测结果仍属于当时版本；最新生产修复及冻结原文绑定评测见[推进报告](semantic-progress-validation-20261019.md)与[v3 合同](semantic-evaluation-v3.md)。

门禁将定性主张的 `content`、`rationale` 和 `source_assertions` 送入共用支持性检查。每个 `quote` 必须与对应的**完整已提供来源上下文**一致；从来源中只截取结论、删去否定或限定条件的子串，不能凭“确实在原文中出现”获得准入。原文披露前缀和完整否定 checkbox 模板单独处理，避免把引文中的原始数字或明确否定误判成模型新增断言。来源上下文本身仍可能是选页、局部摘录或未确认的候选；完整复制该上下文不代表整篇财报已经阅读，也不证明原始披露在经济实质上正确。

当前自动接受能力主要是**完整原文观察和安全边界模板**，例如“仅保留原文，不作额外事实或因果判断。”。完整引文仅进入带来源标签的原文观察；解释字段 `rationale` 和逐行 `reason` 只接受中性边界或程序认证固定模板，不能把另一段真实来源当作当前主张的支持证明。有限规则可拒绝部分明确矛盾；无法可靠确认主张与证据蕴含关系的其他自由改写返回 `CLAIM_SUPPORT_UNVERIFIED`，保留 `needs_review`、原始文字、来源和规则回执。这表示“支持关系未确认”，不等于认定该句话为假。`未证假设` 标签不免除检查，不能凭标签把任意业务原因送入正式结果。

隔离会损失召回：合理同义改写、真实但未逐字披露的解释和有条件推断，也可能被保守门禁挡住。工作流可逐候选隔离；最终输出若仍含不合格自由文字，会进入有限修正重试，重试后仍不通过就保留失败轨迹，不发布该次正式输出。保留下来的引文和边界句更多说明系统控制了新增断言，不能据此声称已经自动完成深层财务原因分析。要减少这类误拒，仍需独立金标准、主张级支持性评测及验证过的推断规则，不能简单放宽字符串规则。

`report_sections` 和 claim `type` 只允许登记的中性标签或指标代码，额外 `limitations` 只允许继承证据包限制或采用安全边界模板；`qualitative_summary` 必须由已检查的主张派生。这样关闭标题、类型和限制字段夹带独立断言的通道。严格数值与公式继续由程序核验、计算和渲染，不能用安全模板代替金额或口径检查。

已完成历史记录在任何写入之前，按保存策略只读校验后返回；失败不覆盖旧记录、不自动重发请求。新策略须新建运行，旧策略检查点不静默复用；未改变输入的检查点复用还要求最终输出策略、工作流策略及已有输出相容。来源未变本身不足以把旧的未验证输出升级为新策略通过。新门禁模块同时纳入复现源码哈希清单；这些工程控制不构成开放领域语义无错误证明。
