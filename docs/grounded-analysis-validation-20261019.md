# 结构化候选、来源补读与披露归因验证

本记录承接 `semantic-remediation-validation-20261019.md`。本轮重点是恢复可用、可检查的正向输出，并把来源准备、模型生成、结构校验、语义支持和最终呈现拆开记录。没有把模型解释全部隔离后宣称分析已经完成。

## 1. 实际新增能力

新增并迭代至 `grounded-report-candidates-v5` 实验入口，复用真实文件扫描准入、单财报版本、SQLite、ModelClient 和请求配置。用户显式选择物理页与子命题，创建请求只登记任务，后台完成来源准备和一次批量调用。四份财报默认分开运行。v2、v3、v4、v5 的请求投影逐版登记，升级当前版本不改变旧记录的请求重构。v5进一步区分数值、变动、原因、调节等任务证据维度，最新真实试验及其仍存错误见第11—12节。

| 阶段 | 实际处理 | 可核对产物与失败边界 |
|---|---|---|
| 原始文件 | 复用共享扫描准入并校验 PDF 哈希 | 未通过扫描或文件变化时停止；不伪造 clean 记录 |
| 旧提取结果 | 冻结原有 retrieval snapshot，不改历史任务 | 部分旧 chunk 去除行首尾空白，不能冒称逐字原页 |
| 本地补读 | 原生 PDF 任务可补读新选页及相邻页 | 单独保存原页文字及哈希；OCR 任务不回退 PDF 文字层；无页、加密或超预算保留缺口 |
| 上下文包 | 绑定文档、父来源、关联及待续读项 | 文档期间只是背景，同页不同列的期间、合并范围及单位不由元数据补全 |
| 程序披露归因 | 支持两列比较原因表、与前表科目及变动率唯一匹配的原因句 | 科目、原因、金额、变动率、两列表头和单位均保留原文 span；不支持结构保持 unknown |
| 模型生成 | 一次输入多个子命题，要求主体、对象、关系、否定、条件、期间、口径、依据与引用 | 响应是待验证候选，引用正确不等于解释正确；不给模型自我认证字段 |
| 引文定位 | v4只接收来源ID和逐字引文，在指定冻结来源中精确检索 | 唯一命中由程序生成坐标及哈希；重复、未命中或未知来源分别登记，不模糊替换；原始候选不改写 |
| 校验与保存 | 原始响应、元数据、字段错误、引用错误和语义未验证状态分别保存 | 重复 JSON 字段、非法枚举、深层 JSON 和意外本地校验异常不丢原始响应、不自动修复或重试 |
| 输出与回放 | 程序披露归因与模型候选分别呈现，重建冻结输入、请求、回执及完整输出 | `candidate_ready` 不覆盖正式报告的最新可用结果；离线回放与当前来源新鲜度分别检查 |

本轮没有迁移 WP4 的正式事实准入状态机。新入口不写严格事实、不向正式结论计数，不以字面观察或候选条数代替子命题完成度。运行中断恢复、桌面端新入口及完整财报分析仍是后续工程项。

| 问题 | 锁定阶段 | 修复与实际边界 |

| 用户选页超出旧提取范围就不能生成 | 来源准备 | 新选页局部补读，原 snapshot 不改；OCR 不走原生文字补读 |

| 深层 JSON 解析或校验异常导致付费响应未保存 | 本地协议校验/序列化 | 限制解析树深度，原文字符串和元数据先保留；拒绝状态不冒充成功 |

## 6. 使用方式

现有鉴权策略照常生效。任务列表：`GET /api/v1/grounded-analyses/tasks`。

```http
POST /api/v1/filings/{filing_version_id}/grounded-analyses
Content-Type: application/json

{"page_numbers":[2,3,4],"obligation_ids":["cashflow_driver_explanation","cashflow_reconciliation"]}
```

返回202和 `analysis_run_id`。随后查询 `GET /api/v1/grounded-analyses/{analysis_run_id}`；离线重建验证使用 `GET /api/v1/grounded-analyses/{analysis_run_id}/replay`。每次仅一个财报版本、最多12个选页和10个注册子命题，未准备好的页不会为了得到空结果先收费；运行失败或中断不会自动再次调用模型。

`GET /api/v1/grounded-analyses/{analysis_run_id}/export`可直接下载供CLI使用的JSON文件，内容是持久化运行字段及原始trace，没有API envelope。下载不会读取PDF、触发模型或重新运行任务，保留原运行状态和失效时间；未运行或无原始响应的记录可以导出，但不冒充可成功回放的记录。

已保存的独立`run.json`可在无数据库、PDF或模型连接时回放：

```powershell
uv run --no-sync python tools/replay-grounded-analysis.py --input run.json --output new-receipt.json
```

输出文件必须是新路径，禁止覆盖输入或已有回执。通过表示冻结输入、请求、响应、引用解析、校验回执与输出可重建；它不证明导出文件具有第三方签名，也不证明财务语义或新模型调用的一致性。原先失败的协议响应也可以被忠实回放为失败。

### 7.1 Q3已确认错误的逐阶段归因

原PDF第2页及其冻结来源均包含：

```text
经营活动产生的现金流量
净额（元）
—
—
40,845,498,000.00
-27.42%
```

原图表头表明后两项是年初至报告期末累计金额及同比；单季横线不解释为0。实际发送请求与冻结来源逐字相同，原PDF对应三页的native text也逐字相同。

模型statement写“未见经营现金流变动原因”，在选页范围内可以合理；但同条`brief_basis`写成：**“经营现金流变动及原因未在所登记页面出现”**。错误已经存在于`raw-response.txt`，解析后的候选未改写它。因此最早可定位于供应商原始生成/返回阶段，不能归咎于PDF未提取或程序展示时错写。

同条typed relation又以现金流净额本身为主语，predicate为未披露、object为空，未编码所缺的是“原因”。这会混淆值、变动、原因及调节四类信息。精确引文和Schema都不能自动区分它们。原4处引文文字都在对应来源存在，3处由模型填写的坐标错误；另一次纯离线quote检索能唯一定位4/4，但没有修改旧候选或证明其语义正确。

另一条归母净利润引用中，raw quote的金额本身正确，但模型给出的区间实际落到扣非净利润行。问题是**原始引用坐标错挂**，并非PDF归母金额错，也并非模型把raw quote金额改成扣非金额。原始逐字段核查见`grounded-q3-live-v2-audit/review.md`及`evidence.json`。

### 7.2 年报正向输出与仍然存在的范围问题

主智能体亲自查看原PDF第40页并逐条读完3条raw候选；独立子智能体另作核查。原页列明2025/2024年、单位元、经营现金流净额59,135,544,000.00/133,453,873,000.00、披露同比-55.69%，原因是购买商品、接受劳务支付的现金增加。模型正向statement和basis保留了公司披露及“非经独立验证因果”的边界，4处引文均可精确唯一定位。

但会计变更候选basis称“页面仅披露资本化率……与现金流数据”，概括过宽：该页还有研发投入占比的勾选及非主营业务整表。调节候选statement限定“本页未找到调节说明”，但其`disclosed + negated`关系没有编码表单勾选的“不适用”状态和页范围；不把它认证成一般的未披露关系。该页“不适用”勾选既不证明公司没有财务异常，也不等于提供完整的净利润→经营现金流桥接表。

本批的具体期间和元单位与原表相符，而来源登记仍是`unspecified`；因此`GROUNDING_SOURCE_CONTEXT_MISMATCH`表示登记上下文尚未认证，不是证明财务期间或金额错误。程序输出另保留3条带表头、单位和原文锚点的公司披露归因；它们不等于自动确认任意模型解释。

原有`unrepresented_obligation_ids`按“是否至少有一条`provenance_valid`候选”计算，并非原始响应是否生成、财报是否披露或任务是否完成。年报两项现金流任务已生成，但因登记上下文未认证仍出现在该字段；不得将其解释为模型没返回、公司没披露原因或分析已完成。独立逐字段核查见`grounded-annual-live-v3-audit/review.md`及`evidence.json`，包括3原页、4处引用及3条程序归因的30个span。

## 8. 尚未解决的实质缺口

1. 通用自由中文解释的语义蕴含没有可靠认证器。Schema、图关系和引用只能解决相应层次，不能证明推断正确；正确改写仍可能被隔离。
2. 披露归因目前只覆盖有限表格/句式，未覆盖任意跨页、表外条件、OCR误识别和全报告长距离依赖。选页输出不能升级为全文判断。
3. 尚无独立多发行人测试金标准；现有受限开发回归不能估计财报准确率、漏报率或外部模型重新生成结论一致性。
4. WP4正式自动校验准入仍未迁移，新实验输出不替代严格金额主流程。不能因多了API或测试就声明正式自动分析已经完成。
5. 后台执行目前依赖进程内任务。避免重复收费的“不自动重试”已实现，但中途崩溃后的人工可解释恢复、跨进程租约和幂等供应商调用尚需实现。
6. 桌面端尚无新实验入口，暂通过API操作；当前没有以新增演示界面替代金融正确性工作。

## 15. 新增两期披露同比的确定性复算

`disclosed_arithmetic_v1`直接从原文重建观察，按同来源、同行、同科目、同单位和逐字表头配对本期/比较期金额及披露比例。不接受模型提供的运算结果，也不把跨表同名科目拼接计算。正比较基数采用`(本期-比较期)/比较期*100`；金额与比例的显示末位均纳入保守舍入区间。区间比较使用精确Decimal交叉乘积，近似商只用于展示；内部Decimal上下文固定，避免调用方精度、舍入模式或trap改变回执。

结果区分显示数值精确相等、在显示精度假设下相容、超出显示精度待核、负基数未评估和零基数未评估。区间相容只表示按“各项四舍五入至显示末位”的明确假设可相容，不认证公司的实际舍入约定。超区间也只是待核，不能自动判公司原披露错误。季度四列表只有本期/累计值和同比时，不倒推比较期再宣称验证了原公式。

真实年报p40全部10行中，7行正比较基数均与披露同比的显示精度相容，3行负基数不套通用增长率。经营现金流净额按59,135,544,000与133,453,873,000复算为约-55.68840179%，与原披露-55.69%相容。投资净额、筹资净额、现金及现金等价物净增加额的比较基数均为负，保留原披露52.97%、1,118.88%、-441.33%而不认证统一增长口径。

这些负基数恰能说明不能统一偷偷换分母：投资净额按带符号分母和按绝对值分母会得到相反方向。当前模块既不选择一种冒称通用口径，也不据未评估状态宣布公司算错。10行87处原文切片、重复提取及保存回执均可重构；Q3p2四列表未倒推，36份历史文件及原PDF字节未改。证据在`disclosed-arithmetic-annual-p40-v1/`；这不是严格事实准入、会计可比性认证或公司无财务异常的结论。
