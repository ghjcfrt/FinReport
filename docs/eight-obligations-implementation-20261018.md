## 3. 三个关键问题的逐阶段拆解

### 3.1 现金流调节表：来源问题与边界问题是两件事

`text-chunk:93` 只有“将净利润调节为经营活动现金流量：”，不能替代完整调节表。实际数表在 `text-chunk:94`，其原文 SHA-256 为 `ff3d713d6091a2302569c211af738f8b405a2ced9ff14da00d00e98570069233`。

在 [h1-batch-completion/trace.json](../tmp/eight-obligations-20261018/h1-batch-completion/trace.json) 第二轮，模型的现金流调节表候选已经通过 `source_resolution=resolved`，但被 `AGENT_COMPANY_DISCLOSURE_EXCERPT_BOUNDARY_REQUIRED` 拒绝。原因是旧 `_cashflow_subtable_units_v11` 只认识主现金流量表的经营活动分部，不认识补充资料中的间接法调节表。该块又包含后续“不涉及现金的重大投资和筹资活动”子表，整块边界与前一独立表格的边界不同。

新增 `cashflow_units.reconciliation_units`，只认证已保存 Docling 来源中可完整闭合的两期调节表：日期与期间表头、净利润起始行、全部调节行、经营现金流净额终止行；后续子表必须具有明确分界。认证绑定父原文、Docling 节点和原页来源，不读取外部文件，不让模型自行指定任意截取区间。

同一份历史原始候选不改一字，通过新策略校验；删去中间行、破坏父来源哈希仍拒绝。新真实试跑使用 `source_unit_id`，由服务端逐字渲染整张调节子表。

原表本期/比较期 CFO 分别为 **31,833,471 / 14,178,310 千元**。程序可计算差额 **17,655,161 千元**、同比约 **124.5223%**，并核对净利润至 CFO 的桥接。原始计算和期间口径继续保存在本地计算记录中。这些勾稽不能独立证明回款改善、结算策略变化或销量增长。

### 3.2 不足模板：不静默修补模型原话

此前原始输出的 assessment 已是合法 `insufficient_evidence`，statement 也使用了固定模板，但 rationale 擅自追加定向说明，因此被 `AGENT_UNREFERENCED_INSUFFICIENCY_REQUIRES_TEMPLATE` 拒绝。这个阶段不是数值提取失败。

现将合法字段组合、两个固定文本和引用角色同时写入 Schema 字段说明及独立任务协议。具体待补材料写入 `material_requirements`。模型重新提交后才验收，原候选、拒绝原因、重交候选分别保存；程序没有把被拒绝的输出替换成合格文本后冒充原始通过。

最终四条无引用不足候选都为：

```text
assessment: insufficient_evidence
statement: 现有材料尚不足以确认本主题事项。
rationale: 尚需核对完整披露，保留证据判断边界。
source_ids / metric_result_ids / calculation_ids / limitation_source_ids: []
```

这只是判断边界。缺材料的任务不标记 completed，报告也不标记完成。

### 3.3 现金流业务原因：保留拒绝，重新形成边界判断

旧候选 rationale 写“现有材料未披露销量、售价、结算方式或回款政策……”，statement 还把应收调节项称为“回款相关项目”。程序以 `AGENT_SEARCH_ABSENCE_IS_NOT_DOCUMENT_ABSENCE` 拒绝，来源解析本身成功。

最终接纳的原始 statement 为：“分析推断：所引调节表仅列示表内调节项目，不能独立支持对经营现金流变动具体业务因果的判断。”其 `evidence_kind=evidence_insufficient`，assessment 为 `insufficient_evidence`，引用 `text-chunk:94`。标签文字不改变其不足类别。

模型另外生成“桥接差额为零”等推断时仍受程序事实边界约束；零差额应由计算记录展示，不能让自由文本冒充计算结果。本轮没有放宽这一规则。

## 4. 主程序变更

- `analysis_agent.py`：引入独立子命题策略 `evidence_obligation_tasks_v1`；每批最多 20 项、每项最多 3 次分析尝试；按任务独立接纳、保留有效候选，仅重交失败或遗漏义务；检索不直接计作分析失败；恢复继承尝试次数与失败历史。
- `source_registry.py`：冻结文件选择及来源身份，累计实际发送的原文授权；按 ID 跨窗口回取并核对文档、原页、原文哈希。未发送、未选文件、内容变化和未知 ID 分别拒绝。
- `cashflow_units.py`：新增上述完整调节子表认证，仅新策略启用。旧 V1–V3 证据策略继续沿用原有单元集。
- `financial_semantics.py`：有限规则检测“非金融企业持有金融资产”被写成“非金融资产类”或主体变为金融企业，以及仅凭桥接表作业务因果解释。保存规则、命中片段和原文区间；不宣称通用语义正确率。
- `_compact_obligation_request`：减少重复进度、历史候选正文与坐标审计细节，保留本轮全部原文、来源指纹、质量标志、真实单元 ID 和完整本地审计数据。
- `report_analysis.py`：报告分析入口显式选用新任务策略；旧严格数值入口默认策略保持兼容。结果域模型增加可选任务状态；旧版本序列化不写空新字段。
